<objective>
Build the single native seam (`evidence/image.py`) that opens raw/dd and E01/EWF images read-only, and the integrity layer (`evidence/integrity.py`) that streams MD5+SHA-256 in one pass, compares against a supplied acquisition hash, re-verifies at end of run, and hard-guards against ever touching the evidence. Delivers INGEST-01 (open raw + E01), INGEST-02 (hash + compare), and INGEST-03 (read-only / never-mounted / re-verify guarantee).

Purpose: This is the load-bearing forensic boundary. Per D-06 and ARCHITECTURE Anti-Pattern 1, pytsk3/pyewf are imported in exactly ONE module so the rest of the system is testable without a real image. Per PITFALLS P1/P2, the source is opened byte-level read-only (never mounted), hashed once at ingest and re-verified at end, failing loudly on mismatch. The host lacks libewf-dev, so the EWF adapter logic is unit-tested against a mocked `pyewf.handle` (01-RESEARCH.md §Environment Availability / A4).

Output: `evidence/` package (image.py, integrity.py) with raw-open, EWF-adapter, streaming-hash, re-verify, and read-only-guarantee tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk image (untrusted evidence) → pytsk3/pyewf | adversarial bytes parsed by native libs at the single seam |
| analysis host → source path | the source must be opened read-only and must never be a mounted filesystem |
| native libs (pytsk3/pyewf) → rest of app | only `evidence/image.py` may cross this boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Tampering / Repudiation | source image open path | mitigate | `pytsk3.Img_Info` / `EWFImgInfo` open the source byte-level read-only; never `mount`/`losetup`; `assert_source_not_mounted` refuses mounted-source paths (PITFALLS P1; ASVS V4). |
| T-1-02 | Repudiation / Tampering | integrity hashing | mitigate | SHA-256 primary (MD5 interop-only) via stdlib `hashlib` (never hand-rolled — V6); compare to supplied acquisition hash PASS/FAIL; re-verify at end of run; mismatch → loud non-zero exit + audit-able error (D-08, PITFALLS P2). |
| T-1-03 | Tampering | evidence modification | mitigate | No write path to the source anywhere in the module; source mtime/size asserted unchanged across open+hash; all output goes to the case dir (INGEST-03, ARCHITECTURE Pattern 3). |
| T-1-02-A | Denial of Service | crafted image (huge/sparse) hashing | accept | Single streaming pass is memory-bounded by chunk size; Phase-1 fixtures are tiny; multi-TB performance tuning is a later concern (PITFALLS performance traps). |
| T-1-02-B | Information Disclosure | native-lib parsing of untrusted bytes | mitigate | Parsing is confined to the trusted, court-validated TSK/libewf libraries at one seam; no network egress; pinned slopcheck-clean versions (V10, PITFALLS P11). |
