<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| evidence image → seam (filesystem.py) | Untrusted disk image bytes; deleted-entry metadata (names, sizes, flags) are adversarial |
| deleted filename → recovered/ write path | A deleted name may contain `../`, control chars, FAT `?`/`_`, or be absolute |
| seam → orchestrator (recover.py) | Only plain ints + a read closure cross; no native object |
| orchestrator → case dir | Only the case dir (recovered/, case.db) is written; source is never written |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01-PATH | Tampering | recovered/ write path from deleted filename | mitigate | `_sanitize_name` + `_confined_target` realpath confinement; deterministic vol/off/meta_addr scheme, never the raw name (D-33/D-34) |
| T-04-01-BOMB | Denial of Service | recovered-content size bomb (huge/sparse deleted file) | mitigate | Honor max_hash_size / ExtractionLimits ethos as a write cap; sparse runs skipped in iter_block_runs |
| T-04-01-REUSE | Spoofing (of findings) | reopened inode reallocated to a live file | mitigate | Re-check `meta.flags & ALLOC` at recover time; classify reallocated inode partial/overwritten, never present its bytes as the deleted file (Pitfall 5) |
| T-04-01-RO | Tampering (forensic soundness) | writing to / altering the evidence source | mitigate | All reads via the seam read_random (no mount/write); re-assert assert_source_not_mounted; only case dir written; Phase-1 re-verify runs (D-42) |
| T-04-01-CLAIM | Repudiation | overclaiming tier/intent in the report | mitigate | Tier copy describes data survival only; honesty test forbids intent/good-bad substrings (D-32) |
| T-04-01-SC | Tampering | npm/pip/cargo installs | accept | No new packages (research audit: none); pytsk3 already pinned/audited in Phase 2 |
</threat_model>
