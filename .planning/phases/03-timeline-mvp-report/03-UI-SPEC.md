# Phase 3 — UI Design Contract

> Visual and interaction contract for the PyAutopsy forensic report. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Context: This Is a Document, Not an App

The "UI" for this phase is a **static, self-contained, offline forensic HTML report** (`reports/report.html`) rendered by Jinja2 (D-22), plus a structured machine-readable sibling (`reports/report.json`, REPORT-04). There is **no routing, no JS framework, no backend, no network/CDN assets, and no interactivity**. The artifact is read by investigators and may be presented as evidence, so the visual contract optimizes for: a defensible document layout, dense-table legibility, forensic honesty (no overclaiming), grayscale-print safety, and a future WeasyPrint→PDF path that the same template must not preclude.

**Inputs are evidence-controlled.** File names, paths, file types, and volume/limitation strings come from the analyzed image and are adversarial. All evidence-derived values render through Jinja2 autoescape (ON); `| safe` / `Markup()` is **forbidden** on any evidence-derived value (Pitfall 3 / Security V5).

**Hard constraints carried from upstream (binding on this contract):**

| Source | Constraint | UI implication |
|--------|-----------|----------------|
| D-22 | HTML via Jinja2; PDF deferred | All CSS inline in a single `<style>` block; no external fonts/scripts/CDN. Layout must degrade to print + a later WeasyPrint path. |
| D-25 | Run metadata segregated from byte-comparable body | Volatile values (generation time, durations, host, run-id) render in a clearly-labeled, comparison-excluded `run_metadata` region (recommended: separate file + a labeled footer). **No `datetime.now()` in the analytical body.** |
| D-27 | Bounded HTML timeline + honest truncation note | HTML shows a capped slice with an unmissable "showing N of M — full timeline in report.json" disclosure. Full timeline lives in JSON only. |
| D-28 | Findings = inventory stats + integrity PASS/FAIL + D-20 limitations | Report sections fixed below; a Limitations section is **mandatory**, stating what the MVP does NOT analyze. |
| PITFALLS P4/P10 | UTC-everywhere, explicit offsets, no overclaiming | All timestamps render with explicit `+00:00` offset; FAT `local-time-inferred` / `assumed_timezone` provenance flags must survive into the report and be visually marked. |
| Determinism | No random ids, no embedded wall-clock in body | No per-render generated IDs, no `<meta>` build dates in the body, deterministic markup so D-25 byte-equality holds. |

## Design System

| Property | Value |
|----------|-------|
| Tool | none (not a React/Next/Vite project — shadcn gate not applicable; this is a Python CLI emitting a static HTML document) |
| Preset | not applicable |
| Component library | none — hand-authored single Jinja2 template with one inline `<style>` block |
| Icon library | none — no external icon font/SVG-CDN (offline). Status conveyed by **text labels + Unicode glyphs from the system font** (e.g. `PASS` / `FAIL`, `✓` / `✗` / `⚠`) plus a non-color cue; never color-only (grayscale-print safe) |
| Font | System font stacks only (no web fonts). Body/UI: `ui-sans-serif, system-ui, -apple-system, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`. Monospace (hashes, paths, offsets, meta_addr): `ui-monospace, "SFMono-Regular", "Cascadia Mono", "Liberation Mono", Menlo, Consolas, monospace` |

**Self-contained mandate:** the template inlines all CSS; it references no `http(s)://` resource, no `@import url(...)`, no web font, no external image. Verifiable by grep: the rendered HTML must contain zero `http://` / `https://` / `//cdn` references in `href`/`src`/`url()`.

## Spacing Scale

Declared values (multiples of 4). Expressed in **`rem` / `px`, never `vh`/`vw`** (viewport units break print/PDF pagination — Pitfall: print-readiness).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Cell padding (dense table rows), inline gaps, badge padding |
| sm | 8px | Compact spacing inside cards, table header padding |
| md | 16px | Default block spacing, paragraph rhythm, table outer margin |
| lg | 24px | Sub-section spacing, card padding |
| xl | 32px | Spacing between major report sections |
| 2xl | 48px | Header block / first-section separation |
| 3xl | 64px | Page top/bottom document margin (screen); print margin handled by `@page` |

Exceptions:
- **Dense forensic tables** (file inventory, timeline) use **4px vertical / 8px horizontal cell padding** to fit many columns/rows legibly — a deliberate compaction, still on the 4-grid.
- Print page margin set via `@page { margin: 16mm; }` (physical units for PDF correctness), not the screen token.

---

## Typography

Sizes in `rem` (base = 16px). **3 sizes + 1 dense-table size; 2 weights.** Monospace is a font-family choice, not an extra size — it inherits the surrounding role's size.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (1rem) | 400 | 1.5 | Prose: methodology, limitations, finding descriptions |
| Label / table | 14px (0.875rem) | 400 (600 for `<th>`) | 1.4 | Table cells, key/value metadata rows, captions, the truncation note |
| Heading | 20px (1.25rem) | 600 | 1.25 | Section headings (Findings, Timeline, Evidence Hashes, Limitations …) |
| Display | 28px (1.75rem) | 600 | 1.2 | Report title (case/evidence identity) — appears once, in the header |

Rules:
- Exactly **two weights**: 400 (regular) and 600 (semibold). No 300/500/700/800 — keeps grayscale + print rendering predictable across system fonts.
- Hashes, file paths, inode/meta_addr, byte offsets, ISO-8601 timestamps render in the **monospace family** at the surrounding role's size (so columns align and a SHA-256 doesn't wrap mid-digest where avoidable).
- Long hashes/paths use `overflow-wrap: anywhere` / `word-break: break-all` inside their cell so a 64-char SHA-256 never forces horizontal page overflow in print.
- Headings use `break-after: avoid` and tables use `break-inside: avoid` where small, for print/PDF pagination friendliness.

## Color

A **near-monochrome, ink-on-paper** palette. The document must remain fully legible and unambiguous in **grayscale print** — therefore color is never the sole carrier of meaning (every status also carries a text label and/or glyph). The 60/30/10 split is interpreted for a document:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` page / `#1a1a1a` ink | Page background + body text. Default reading surface. |
| Secondary (30%) | `#f4f4f5` zebra/strip + `#52525b` muted text + `#d4d4d8` borders | Table zebra striping (alternate rows), section card surfaces, rules/borders, captions and the "muted" provenance/limitation annotations |
| Accent (10%) | `#1d4ed8` (blue) | Reserved — see list below. Used sparingly; degrades to a darker gray + underline/label in print. |
| Destructive / Fail | `#b91c1c` (red) | Integrity **FAIL** status and hard-error/limitation emphasis only — always paired with the literal text `FAIL` and a `✗`/`⚠` glyph so grayscale still reads. |
| Success / Pass | `#15803d` (green) | Integrity **PASS** status only — always paired with literal `PASS` and `✓`. |

Accent (`#1d4ed8`) reserved for:
- Section heading rules / the report-title underline (structural emphasis).
- The header band that identifies the case/evidence (single most-important identity block).

Accent is **NOT** used for: arbitrary text emphasis, table headers (those use weight 600 + secondary background), every border, or "all important things." Status semantics use the dedicated Pass/Fail colors, never the accent.

**Forensic-honest, print-safe status encoding (binding):**

| State | Color | Text label (always present) | Glyph | Notes |
|-------|-------|------------------------------|-------|-------|
| Integrity verification PASS | success green | `PASS` | `✓` | acquisition-compare + end-of-run re-verify (D-28) |
| Integrity verification FAIL | destructive red | `FAIL` | `✗` | must be visually prominent (top of report) |
| Allocated file/event | ink (default) | (none needed) | — | the normal case |
| Deleted / unallocated entry | ink + secondary-muted tag | `deleted` / `unallocated` | — | rendered as a text tag in its own column, not color-only |
| FAT local-time-inferred timestamp | secondary-muted | `local-time-inferred` | `⚠` | provenance flag from Phase 2 `attributes`; must survive to report (Pitfall 10) |
| Assumed timezone | secondary-muted | `assumed tz: <zone>` | `⚠` | from `attributes.assumed_timezone` |
| Encrypted / unsupported volume limitation | destructive-muted | `limitation: <reason>` | `⚠` | D-20 / D-28 — never silently dropped |

All status colors must satisfy WCAG AA contrast (≥4.5:1) against the white page for legibility in evidence presentation.

## Report Section Hierarchy (canonical order)

The HTML report and the JSON report present the **same sections in the same fixed order** (determinism + reviewer familiarity). This order is the visual contract for the executor:

1. **Header / Identity band** — report title, case ID, examiner, evidence ID, acquisition source. (accent band)
2. **Integrity Verification result** — `PASS`/`FAIL` for acquisition-hash compare and end-of-run re-verify, prominent near the top (D-28). The single most safety-critical signal.
3. **Methodology + Tool Versions** — what was done, with **pinned `tsk_version` + `pyautopsy_version`** (D-26 / CLI-02) recorded verbatim.
4. **Findings** (D-28):
   - 4a. **Inventory summary stats** — file count, directory count, deleted-entry count.
   - 4b. **Per-volume breakdown** — one row per volume (id/offset, fs_type, counts).
   - 4c. **File-type distribution** — type-by-signature counts, ranked.
5. **Evidence Hashes** — source `md5` / `sha1` / `sha256`, monospace, full width, break-all.
6. **Timeline (bounded)** — capped, D-26-ordered slice with the truncation disclosure (D-27).
7. **Limitations** — explicit: D-20 encrypted/unsupported volumes **and** the standing MVP disclaimer of what is not yet analyzed (no recovery, no log parsing, no search — Phases 4/5). Mandatory; never omitted even when empty of volume limitations.
8. **Run Metadata (non-analytical)** — clearly labeled, comparison-excluded footer (D-25). Generation timestamp, durations, host, run-id live ONLY here.

**Table conventions (sections 4b, 4c, 6):**
- Zebra striping (secondary `#f4f4f5` on alternate rows) for dense-row tracking.
- `<th>` weight 600 on secondary background; sticky header (`position: sticky; top: 0`) acceptable for the **screen/HTML** timeline table only (it is inert in print, which is fine).
- Column priority for the timeline (left→right, matching D-26 order so the eye follows the sort): **timestamp (UTC, +00:00) → volume → path → event type (M/A/C/B) → meta_addr → provenance flags**. Path is the flexible-width column; timestamp/type/meta_addr are fixed monospace.
- Deleted/unallocated status is its own labeled column, not a row color.

## Bounded Timeline Disclosure (D-27 — honesty is load-bearing)

- The HTML timeline renders **at most `cap` events** (default cap = **2000**, configurable; chosen to keep HTML well under multi-hundred-MB and human-scannable — Assumptions Log A3).
- When the full timeline exceeds the cap, an **unmissable disclosure** renders immediately above (and below) the table, at label size, with `⚠`:
  > **Showing {N} of {M} timeline events.** This HTML view is truncated for readability. The complete, unabridged timeline is in `report.json` (REPORT-04).
- The disclosure must **state real numbers** (`N` shown, `M` total) — never a vague "some rows hidden." If `N == M` (not truncated), no disclosure is shown (avoid false alarm).
- The bounded slice is the **first `cap` events in D-26 order** (deterministic, not a random sample). JSON carries all `M`.
- The HTML timeline must read a bounded query/slice (`LIMIT cap` / `sorted[:cap]`) — it must **never** materialize the full multi-million-event list then slice (Pitfall 5 / resource exhaustion).

## Copywriting Contract

No CTAs/buttons exist (static document). The "copy" surface is **status labels, disclosures, and honest section framing**. Every string below is the prescriptive wording for the executor; wording is part of the forensic-honesty contract.

| Element | Copy |
|---------|------|
| Primary CTA | N/A — static report, no interactive actions. (The user's "action" is the CLI `pyautopsy analyze`; no in-document controls.) |
| Report title | `PyAutopsy Forensic Report — Case {case_id}` |
| Integrity PASS | `Integrity verification: PASS — source hash matches acquisition value and end-of-run re-verification.` (green, `✓`) |
| Integrity FAIL | `Integrity verification: FAIL — source hash mismatch. This report's findings may not correspond to the originally acquired evidence. Re-acquire and re-verify the source.` (red, `✗`) |
| Empty timeline state | `No timeline events were produced. No filesystem MACB timestamps were recorded for the analyzed volume(s).` (states the cause, not just "empty") |
| Empty inventory state | `No files were inventoried. The volume(s) may be empty, unsupported, or encrypted — see Limitations.` |
| Timeline truncation note | `Showing {N} of {M} timeline events. This HTML view is truncated for readability; the complete timeline is in report.json.` |
| MVP limitations (standing) | `This is an MVP report. It covers filesystem inventory, MACB timeline, and integrity verification only. It does NOT include deleted-file recovery, known-file (NSRL) filtering, log analysis, super-timeline, or content search. Absence of a finding here does not mean absence of evidence.` |
| Volume limitation line | `Limitation — Volume {id} ({fs_or_reason}): {reason}. This volume was not analyzed; results elsewhere exclude it.` |
| FAT/inferred-time flag caption | `Timestamp provenance: local-time-inferred (timezone assumed: {zone}). Offset shown is assumed, not recorded by the filesystem.` |
| Error state (render-level) | `A section could not be rendered: {reason}. This does not affect the integrity result above; consult report.json for the complete machine-readable data.` |
| Run-metadata header | `Run Metadata (non-analytical — excluded from the reproducible report body)` |
| Destructive confirmation | N/A — the report performs no actions; nothing destructive in this surface. |

**Tone rules (forensic, binding):**
- Findings describe **artifacts + method**, never human intent. Forbidden phrasings: "the user deleted…", "the suspect accessed…", "this proves…". Use "the filesystem records…", "metadata indicates… (assuming clock accuracy)".
- Never imply court admissibility (out-of-scope per PROJECT.md / Pitfall 11).
- Every absence is phrased as "not present in available data," never "did not happen."

## Print / PDF Readiness (forward path to deferred WeasyPrint)

The template must already be print-correct so the deferred PDF path (D-22) is purely additive:
- `@page { size: A4; margin: 16mm; }` plus a `@media print` block (hide the sticky-header behavior, ensure backgrounds via `print-color-adjust: exact` for zebra/status only where needed).
- Use **physical/relative units** (`mm`, `rem`, `pt` in print context) — **no `vh`/`vw`/`vmin`** anywhere (they have no meaning in paginated PDF).
- `break-inside: avoid` on small cards (integrity result, per-volume rows); `break-after: avoid` on headings.
- Long monospace strings (hashes/paths) wrap with `overflow-wrap: anywhere` so nothing is clipped off the page edge.
- No reliance on JS, hover, or scroll for any meaning — everything is visible in static/print render.

---

## Determinism Constraints on Markup (D-25 / CLI-02)

- **No** `datetime.now()`, run-id, host, or duration in the analytical body markup — those go only in the Run Metadata footer region, which the byte-comparison test strips/excludes.
- **No** randomly generated DOM ids, nonces, or per-render tokens.
- Jinja2 environment: `autoescape=select_autoescape(["html","j2"])`, `trim_blocks=True`, `lstrip_blocks=True`, `keep_trailing_newline=True` so whitespace is editor-independent and deterministic.
- Iterate the timeline over an **already-sorted list** (D-26 total order: `ts → volume_id → volume_offset → path → event_type → meta_addr`); never iterate a dict/set in the template.
- Recommended (Open Question 2, option b): render run metadata to a **separate** region/file so `report.html` itself is whole-file byte-deterministic alongside `report.json`.
