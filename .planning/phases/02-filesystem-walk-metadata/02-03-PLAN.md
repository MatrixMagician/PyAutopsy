<objective>
The final Phase 2 enrichment slice: per-file integrity hashing and content-based
type identification. Compute MD5 + SHA-1 + SHA-256 for every allocated regular
file in a single streaming pass (META-04, D-17) reusing the Phase 1 single-pass
idiom, with empty-file sentinels, an optional `--max-hash-size` skip, and
non-regular entries left unhashed; and identify each regular file's type by
content signature via python-magic (META-05, D-19) — never by extension.

Purpose: Hashes are the join key for Phase 4 known-file filtering and the
integrity backbone of the report; content typing is the honest, extension-proof
file identification. Both read read-only through the TSK File object (D-05/P1).
Output: `hash_file` added to `integrity.py`; `core/walk.py` populates `md5`,
`sha1`, `sha256`, and `file_type` (and hash-skip `attributes`) for regular files.
</objective>
