<objective>
The first end-to-end Phase 2 vertical slice: walk a supported filesystem and
produce a normalized per-file inventory in the case store. Delivers META-01 in
full — path, size, inode/MFT address, allocated/unallocated status — across
bare-FS (offset 0) and partitioned images with per-volume tagging (D-15),
records every entry including deleted ones (D-18), surfaces encrypted/unsupported
volumes as explicit limitation findings (D-20), and proves the read-only
guarantee holds across the whole walk (D-05/P1). Establishes the D-14 FS-layer
native seam allowlist as an executable reality.

Purpose: This is the demonstrable spine of the phase — after this slice an
examiner can run `pyautopsy walk <image> --case ...` and get rows. Plans 02 and
03 enrich those rows (MACB/owner, hashes/type) without changing the walk shape.
Output: `files` + `volume_limitations` tables, `FileRow`/`VolumeLimitation`
models, `insert_files`/getters, the `evidence/filesystem.py` seam, the
`core/walk.py` orchestrator, and the `pyautopsy walk` CLI command. The columns
for MACB/owner/hash/type are added to the schema now (interface-first) and left
null until Plans 02-03 populate them.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk image → FS seam | The crafted/corrupt filesystem image is untrusted input crossing into pytsk3 recursion. |
| FS seam → orchestrator | FileEntry names/sizes are attacker-controlled data flowing into the case store. |
| orchestrator → source | The walk must never write or mount the read-only evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-01-CYCLE | Denial of Service | `filesystem.walk_fs` recursion | mitigate | `_seen` inode set + skip `.`/`..` before recursing into any DIR (Pattern 2/Pitfall 4); $OrphanFiles VIRT_DIR handled explicitly. Verified by `test_recursion_correctness`. |
| T-2-01-NAME | Tampering | hostile filenames (traversal/control/non-UTF8) | mitigate | Names decoded `utf-8`/`errors="replace"` and stored as DATA ONLY in case.db — never used as a path to write/extract (no extraction in Phase 2). Security V5. |
| T-2-01-ENC | Availability/Integrity | encrypted/unsupported volume (`FS_Info` OSError) | mitigate | D-20: orchestrator catches `OSError` per volume, records a `volume_limitations` finding, continues (Pattern 7/Pitfall 6). Verified by `test_unsupported_volume_records_limitation`. |
| T-2-01-RO | Tampering | walk reading/altering the source | mitigate | All reads go through the TSK `File` byte-reader closure; `assert_source_not_mounted` re-asserted; never mount (D-05/P1). Verified by `test_source_unchanged_after_walk`. |
| T-2-01-SEAM | Tampering | native binding sprawl | mitigate | D-14 allowlist enforced by `test_seam_allowlist.py`; only image.py + filesystem.py import pytsk3. |
</threat_model>
